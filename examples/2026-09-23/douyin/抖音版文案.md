## 标题

你点的是 Opus 5.5，跑的可能不是它

## 摘要

被标红的请求，会被转交给更旧的模型

---

## 正文

有件小事，这一阵子值得每个把 AI 接进生产流程的人看一眼。

Anthropic 在 9 月 22 日发布 Claude Opus 5.5。降价幅度不小：输入输出各降五分之一，缓存读取直接砍掉六成。官方口径是典型任务成本比上一代低大约四成。

但发布材料里还藏着一条更值得读的东西。

**一、不是所有请求，都由 Opus 5.5 回答**

Opus 5.5 沿用了一套面向网络安全、生物、前沿模型研发的安全分类器。当请求被判定落入这三类领域，它不会被直接拒绝，而是转交给更旧的模型：

· 网安类 → Opus 4.8

· 生物与前沿研发类 → Opus 5

官方的表述是「透明地重路由」。可这个词值得推敲一下：如果真透明，你不需要翻文档，才知道自己正在跟谁说话。

**二、同一套机制，两种行为**

整件事里，这一处跟你的代码关系直接。

官方自己的产品里，这个回退自动发生。可到了 API 上，得开发者自己去开。

没开的时候，被拦下的请求就是被拦——而且它以 HTTP 200 返回。

HTTP 200，在几乎所有编程语言里等于「成功」。真正的拒绝原因，写在返回内容里。

监控、重试、计费，只要有一处只认状态码，那次被拒绝的调用就会被记成一次成功。

再想一层：一条 agent 流水线可能跑十几步。中间若有几步被换了模型，你的提示词调优、token 预算、行为假设，全都建立在一个不成立的前提上。

**三、一处没绕过来的取舍**

Anthropic 早前那代模型的说明里，记过一笔：回退会让它更容易被提示注入攻破，因为旧模型本身就没那么结实。他们后来说已经加强了。

但把这个取舍摊开看：为了照顾一类风险，另一类风险反而被放大了——接手的那一位，抗注入能力本来就更差。

这不是指控。只是一个该被摆到台面上的权衡。

**我的判断**

有人会问，这算不算有点不厚道？我觉得谈不上。这件事写进了模型卡，也留了申请通道——做生物研究的机构可以走验证计划，做安全的分档权限也在扩。

真正变的是一件更基础的事：以前挑模型，比的是它有多能干；现在你买到手的，是它有多能干，外加一套你没参与制定的替换规则。

名字是确定的。执行的是策略。

**今天就能查的三件事**

1. 你的场景是否落在三类分类器范围内（做生物、安全、模型研发方向的，这是必查项）

2. 把拒绝原因字段加进监控与重试逻辑，别只看状态码

3. 把「模型身份」当变量、而不是常量来设计
