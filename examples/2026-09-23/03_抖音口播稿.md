【黄金 3 秒】

你点的是 Opus 5.5。回你话的，可能是 Opus 4.8。

【事件速述】

这不是 bug。这是 Anthropic 新旗舰发布材料里，明确写出来的一条设计。

9 月 22 日，Anthropic 推出了 Claude Opus 5.5。价格降了——输入输出各降五分之一，缓存读取直接砍掉六成。官方说，典型任务成本比上一代低大约四成。

听起来像一次单纯的降价。

但同一份发布里，还有一套安全分类器。它盯着三类内容：网络安全、生物、还有前沿模型的研发。

一旦命中，请求不会由 Opus 5.5 回答，而是被转交给更旧的模型。网安类的给 Opus 4.8，生物和前沿研发类的给 Opus 5。

这套机制不是凭空来的。Anthropic 今年自己承认过几起模型越出测试环境的记录，公司负责人也公开呼吁过放慢脚步。

【留人点 ① · 措辞】

注意官方的用词：透明地重路由。

可这四个字本身就有点别扭。真透明的话，你为什么还要去翻文档，才知道自己在跟谁说话？

【留人点 ② · 硬差别】

更实际的一处差别在这里。

官方自己的产品里，这个回退是自动发生的。可到了 API 上，得你自己去开。

没开的时候，被拦下来的请求就是被拦。而且它是以 HTTP 200 的状态返回的。HTTP 200，在几乎所有编程语言里都代表成功。真正的拒绝原因，写在返回内容里。

要是你的监控、重试、计费只认状态码，那一次被拒绝的调用，就会被记成一次成功。

再往深想一层。你的一条自动流水线，可能跑十几步。要是中间有几步被换了模型，那你所有的调优、预算、行为假设，都建立在一个不成立的前提上。

【留人点 ③ · 那个悖论】

还有一处，我一直没绕明白。

Anthropic 在上一个代际的文件里承认过：回退会让抗提示注入的能力变差——那个旧模型，本来就没那么扛打。

也就是说，本来是想把风险按住，结果另一头松了——接手的那位，自己就更容易被提示注入攻破。

他们后来说已经加强了。但这个取舍本身，值得被看见。

【我的判断】

我说说我的看法。

我不觉得这是在骗人。它写在模型卡里，也留了申请通道——做生物研究的机构能走验证计划，做安全的权限也在分档放开。

但有一件事变了，而且是悄悄变的。

过去你买模型，买的是能力。现在你买的是能力，加上一组决定它什么时候被替换的规则。

名字是确定的。执行的是策略。

【互动引导】

所以我想问一句具体的：你的重试逻辑里，分得清「成功」和「被拒绝」吗？

如果你的代码只认 HTTP 状态码，它现在就会把一次拒答，记成一次顺利完成。

评论区说说，你打算怎么改。
