# 话题性 / 争议性评分细则

选题决定成败。写得好但没人关心，等于白写。这份细则用来把「这条值不值得做」变成可复算的判断。

## 六个维度

每条候选按 0–5 分打分，满分 25 分（合规风险为扣分项）。

### 1. 冲突性（0–5）

有没有明确的、可陈述的对立面？

| 分值 | 判定 |
|---|---|
| 5 | 两方公开对垒，且有可供引用的原话（如 A 点名 B、B 回怼） |
| 3 | 存在结构性张力，但双方未正面交锋（如技术路线之争） |
| 1 | 只有单方陈述，没有对立面 |
| 0 | 纯发布通告（"某公司发布某产品"） |

### 2. 认知反差（0–5）

结论是否违反常识直觉？反差的强度决定标题的爆发力。

| 分值 | 判定 |
|---|---|
| 5 | 完全反直觉且有数据支撑（越快反而越慢、越省反而越贵） |
| 3 | 部分反直觉，需要解释才成立 |
| 1 | 符合预期，只是规模更大 |
| 0 | 完全在意料之中 |

### 3. 切身相关（0–5）

普通人的工作、钱包、隐私、安全感会不会被影响？

| 分值 | 判定 |
|---|---|
| 5 | 直接改变读者的日常工作方式或收入 |
| 3 | 影响行业，间接传导到个人 |
| 1 | 只在从业者圈层内相关 |
| 0 | 纯技术细节，与个人无关 |

### 4. 讨论热度（0–5）

是不是已经在被讨论？无人讨论的选题要靠内容硬撑，成本高。

| 分值 | 判定 |
|---|---|
| 5 | 技术圈 + 社媒双线在吵，多平台可见 |
| 3 | 单一圈层内热度高 |
| 1 | 只有零星讨论 |
| 0 | 无人讨论，需要教育市场 |

### 5. 可验证性（0–5）

能不能拿到硬数据或原始信源？没有信源支撑的争议是危险的。

| 分值 | 判定 |
|---|---|
| 5 | 有原始文件、官方数据、当事人原话，且多源一致 |
| 3 | 有主流媒体报道，但缺乏一手信源 |
| 1 | 仅单一二手源 |
| 0 | 纯传闻，无法核实 |

**信源不足两条的候选，直接淘汰，不进入打分。**

### 6. 合规风险（0 或 −3）

命中任一条红线即扣 3 分，且**不得靠其他维度的高分抵消**——扣分后若仍排第一，写作时必须收紧表述。

红线清单见 `SKILL.md` 的「红线自查」一节。

## 选择规则

1. 取总分最高者。
2. **最高分 < 18 分**：当天不出稿，改为产出 `01_选题简报.md`，说明候选与落选原因。宁可空一天，不硬凑。
3. 出现并列：选**可验证性**更高的那条。
4. 与近 3 天已推送选题**主题重复**的，降 5 分处理（见 `memory/automations/` 下的历史记录）。

## 判定示例

**示例 A —— 应选中**

> 某前沿模型在自主编码实验中，35 小时产出 7.5 万行代码、花费 1200 美元，作者结论是"没创造价值"；同时有开发者指出模型会判断"没人会看"从而改变编码方式。

- 冲突性 4（开发者社群内部分歧明显，有对立原话）
- 认知反差 5（能力最强 ↔ 产出无用，强反差）
- 切身相关 4（直接关系每个用 AI 写代码的人）
- 讨论热度 4（技术圈集中讨论）
- 可验证性 5（有原始博客、可复算的数字）
- 合规风险 0
- **合计 22 → 选中**

**示例 B —— 应淘汰**

> 某公司发布新款具身智能机器人，宣称多项能力提升。

- 冲突性 0（纯发布通告）
- 认知反差 1
- 切身相关 2
- 讨论热度 2
- 可验证性 2（只有厂商自评）
- **合计 7 → 淘汰**

**示例 C —— 高分但需收紧**

> 两家公司因数据来源合法性爆发公开争执，其中一方点名另一方。

- 冲突性 5、认知反差 3、切身相关 3、讨论热度 5、可验证性 3
- 合规风险 −3（涉及未决争议，点名具体公司）
- **合计 16 → 低于 18，不做主推**；若当天无更好选题，只能写成「行业现象」而不点名具体主体。

## 打分记录格式

写在 `01_选题评分.md` 里，表格化：

```markdown
| 候选 | 冲突 | 反差 | 相关 | 热度 | 可验证 | 风险 | 合计 |
|---|---|---|---|---|---|---|---|
| 标题A | 4 | 5 | 4 | 4 | 5 | 0 | 22 |
| 标题B | 2 | 1 | 3 | 3 | 2 | 0 | 11 |
```

再补一段「选定理由」和一条「备选」。
